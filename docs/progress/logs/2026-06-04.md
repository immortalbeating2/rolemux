根据用户要求，使用 Superpowers brainstorming 流程，为 RoleMux 新增“大任务拆分、worker 分发、同 provider 多实例和独立 merge 阶段”输出设计文档。

## 设计结论

- 生命周期采用 `split -> dispatch -> merge`。
- `split` 生成标准 subtask manifest，不执行 worker。
- `dispatch` 读取 manifest 并按 provider 配额或 worker 总数分发。
- worker 主语义为 `codex:2,claude:1,agy:1`，快捷语义为 `--workers N --providers codex,claude`。
- 写代码子任务默认使用独立 git worktree。
- 默认不自动合并 worker 改动；`merge --auto-merge` 才尝试无冲突合并。
- Herdr 可作为后续可选 backend，不作为第一版默认依赖。
- AI 易用性优先通过 Codex/Claude 插件或 Skill 调用 CLI，不在第一版引入 MCP。

## 风险与后续建议

- 该设计会影响 CLI 对外契约、task artifact schema、Skill 触发规则和 README，需要作为大功能分阶段实施。
- 自动 planner 拆分的输出稳定性风险较高，建议先落地 manifest schema、validate 和 dry-run。
- 并行写代码必须默认 worktree 隔离，不应让多个 provider 同时写主工作区。
- 当前第一阶段仍是 preview-only：真实 worker 执行、git worktree 创建、patch 收集和 `merge --auto-merge` 尚未实现。
