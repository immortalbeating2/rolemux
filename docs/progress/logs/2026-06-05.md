- 直接用 Node `spawn` 复现 RoleMux 当前行为时，若不显式关闭 child stdin，Codex 输出 `Reading additional input from stdin...` 后等待，60 秒未返回。
- 使用同一 Codex exe、同一 prompt，但设置 `stdio: ['ignore', 'pipe', 'pipe']` 后，Codex 不再卡在 stdin；在临时非 git 目录中继续执行到 trust/git repo 检查并返回非零；在 RoleMux git 仓库目录中可完成非交互执行，返回 `OK`，exit code 0。
- `--json` 模式同样在关闭 stdin 后可完成，stdout 输出 JSONL 事件并包含最终 agent message。

根因结论：

- 本次 RoleMux 调用 Codex 卡住的首要原因不是登录失败、网络不可达或 TTY 必须存在，而是 RoleMux 的 `src/core/process-runner.ts` 当前 `spawn(...)` 未显式关闭 stdin，导致 Codex `exec` 在非交互管道环境中尝试读取额外 stdin 并等待 EOF。
- Claude 分支没有同样卡死，是因为 Claude CLI 在无 stdin 数据时会发出 warning 后继续执行；Codex CLI 行为更严格，会等待 stdin EOF。

建议后续修复：

- 在 `runProcess` 的 `spawn` 选项中显式设置 `stdio: ['ignore', 'pipe', 'pipe']`，保持 stdout/stderr 捕获，同时不给 provider CLI 保留可读 stdin。
- 为 process runner 或 Codex provider 增加回归测试：模拟会等待 stdin EOF 的 provider，确认 RoleMux 不会让子进程因未关闭 stdin 而挂起。
- 可选增强：Codex adapter 后续可考虑为机器可读执行增加 `--json` 或 `--output-last-message`，但这属于输出协议设计变更，应单独评估。
