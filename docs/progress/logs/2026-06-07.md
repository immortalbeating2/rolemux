## 复测结论

### Agy

- 真实 CLI：`C:\Users\peng8\AppData\Local\agy\bin\agy.exe`，版本 `1.0.6`。
- 多种非交互参数形态均未产生 stdout/stderr：
  - `agy --print <prompt> --print-timeout 20s --add-dir .`
  - `agy --prompt <prompt> --print-timeout 20s --add-dir .`
  - `agy -p <prompt> --print-timeout 20s --add-dir .`
- 使用 `--log-file` 后，Agy 日志前段会出现 `You are not logged into Antigravity`，但后段又显示 silent auth 成功、创建 conversation、调用 `streamGenerateContent`。
- 用户交互式终端截图也显示 Agy 已登录并选中模型。
- 进一步搜索日志发现 `text_drip.go` 记录 `length=6`；测试 prompt 期待 `AGY_OK`，长度正好为 6，说明模型结果很可能已进入 Agy 内部渲染/stream 路径。
- 因此更准确的根因不是“用户未登录”，而是当前 Agy 1.0.6 的非交互 `--print` 路径没有把模型文本写到父进程 stdout。RoleMux 通过 stdout/stderr 获取 provider 输出，所以无法把该结果视为有效完成。

### Codex

- 真实 CLI：`codex-cli 0.133.0`，`codex exec` 运行日志中显示 `OpenAI Codex v0.137.0-alpha.4`。
- 简单任务可成功：让 Codex 只读 `AGENTS.md` 并返回第一行标题时，默认、`--sandbox read-only`、`--sandbox workspace-write` 均可返回内容。
- 复杂多文件审查任务可稳定复现失败：Codex 进程 exit 0，但输出和 stderr 包含 `windows sandbox: CryptUnprotectData failed: 2148073483`，并自报无法完成本地文件读取。
- `--sandbox read-only` 没有解决该问题；为了遵守项目安全默认值，本轮没有把危险 bypass 或 `danger-full-access` 设为默认。
- 因此根因不是 RoleMux 未关闭 stdin 或 adapter 无法启动 Codex，而是 nested Codex 在 Windows sandbox 下执行本地工具读取时失败。RoleMux 能修的是“不要把该类自报失败误判为 success”，不能替 Codex CLI 修复底层 Windows sandbox。

## 为什么需要做

- Agy 非交互 print mode 不写 stdout 时如果仍被标记 success，会让三 CLI dispatch 报告出现假阳性：看起来三个 worker 都完成，实际 RoleMux 没有捕获到任何模型输出。
- Codex nested worker 遇到 `CryptUnprotectData failed` 时，CLI 进程仍可能 exit 0；如果 RoleMux 只看 exit code，会把“任务未完成”保存为 success，后续 `dispatch --resume`、报告和用户判断都会被误导。
- Provider 运行耗时必须可信。Agy 未登录复测等待约 41 秒，如果 metadata 显示 1ms，会削弱诊断和回归分析价值。
- 默认不能用危险 bypass/sandbox 参数绕开问题；必须把安全降级做成用户显式 opt-in。

### 问题原因拆解

真实复测显示 Codex nested worker 的失败并不是一个单点问题，而是三层问题叠加：

1. Windows npm shim 启动问题：直接 `spawn('codex.cmd', ..., shell:false)` 会同步抛出 `EINVAL`，直接 `spawn('codex', ...)` 在 RoleMux 中会出现 `EPERM`。修复为 Windows 下用 `cmd.exe /d /s /c codex.cmd` 参数数组包装。
2. 仓库上下文污染问题：nested Codex 在 RoleMux 仓库目录启动时，会自动受到 `AGENTS.md`、Codex 插件、项目规则和会话规则牵引，主动读取本地文件；在当前 Windows sandbox 下触发 `CryptUnprotectData failed`。修复为 readonly context-pack worker 在系统临时空目录执行，只通过 prompt 获得 allowlist 文件内容。
3. 多行 prompt argv 截断问题：Codex 通过 `cmd.exe` 包装后，如果把完整 prompt 当作命令行参数传入，真实 stderr 只显示 user `# Role`，模型输出 “What role should I take for this task?”。修复为 Codex prompt 走 stdin，process runner 写入 stdin 后立即关闭 EOF。
