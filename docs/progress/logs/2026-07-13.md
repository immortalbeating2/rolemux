# 2026-07-13 开发日志

## 目标

将官方 Grok Build CLI 作为 RoleMux 第四个 provider `grok` 接入现有插件与执行链，不新增依赖，不增加 Grok 宿主安装面，不默认降低权限边界。

## 实现

- 核对本机官方 CLI：`@xai-official/grok`，`grok 0.2.99`，非交互入口为 `--single`。
- 新增 `src/providers/grok.ts`，参数为 `--cwd`、`--output-format plain`、`--no-subagents`、`--no-memory`、`--verbatim`、`--single <prompt>`。
- 未传入 `--always-approve`、`bypassPermissions` 或其他危险权限参数；sandbox 继续使用 Grok 原生 `GROK_SANDBOX`。
- 新增共享 `providerNames` 与 `isProviderName()`，让 registry、CLI、doctor、run/fallback、worker pool 和 manifest schema 统一接受 `grok`。
- `ROLEMUX_PROVIDER_GROK_COMMAND` 与 `ROLEMUX_PROVIDER_GROK_ARGS_PREFIX` 自动复用现有 mock override 机制。
- 更新通用 Skill、配置模板、README、AGENTS、产品 spec、M2 阶段文档、代码规范、状态和时间线。
- 新增设计文档与实施计划：
  - `docs/superpowers/specs/2026-07-13-grok-provider-design.md`
  - `docs/superpowers/plans/2026-07-13-grok-provider.md`

## 风险与后续

- 未执行会消耗远端模型额度的真实 Grok 任务；当前认证证据覆盖本机 CLI 存在、dry-run、mock execution 和 task artifact。
- 完整 `npm audit --audit-level=high` 报告未改动的 dev dependencies 中 Vite 1 个 high、esbuild 1 个 low；运行时依赖 audit 为 0。依赖升级应作为独立任务处理，避免混入 provider 功能改动。
- 已打开的 Codex session 通常不会热加载刷新后的 Skill；新 session 会读取更新后的插件 cache。
