# 2026-07-31 OpenCode provider 开发日志

## 目标

将本机 OpenCode CLI 作为第五个 RoleMux provider `opencode` 接入现有 adapter、doctor、run/fallback、worker pool、manifest、Skill、配置和监控链路，不新增运行时依赖或专属 TUI。

## 设计确认

- 本机 `opencode --version` 为 `1.18.10`。
- 非交互入口为 `opencode run [message..] --dir <workdir>`。
- 默认使用 `--pure` 隔离外部插件，不使用被 OpenCode 标为危险的 `--auto`。
- 固定文本探针与临时文件只读探针均返回退出码 `0` 和非空 stdout。
- Windows npm `.cmd` shim 会重新解释 `%PATH%` 并截断多行参数；adapter 必须直接启动官方包内 `opencode.exe`。
- OpenCode 输出复用现有 PTY 控制序列清理、timeout、cancel 与 monitor/TUI，不增加平行执行系统。

## 实现

- 新增 `src/providers/opencode.ts`，Windows 直接解析官方 `opencode-ai/bin/opencode.exe`；macOS/Linux 使用 `opencode`。
- 命令固定为 `run --pure --dir <workdir> --format default <prompt>`，不增加 `--auto`。
- 将 `opencode` 加入共享 `providerNames` 与 adapter registry，doctor、CLI、worker pool 和 manifest schema 自动继承。
- OpenCode 使用普通 process runner；`stripTerminalOutput` 复用已有终端控制码清理，同时处理 stdout 与 stderr，避免为非交互 CLI 引入 ConPTY 生命周期。
- 更新 config、README、通用 Skill、AGENTS 与 M2/总 spec。
