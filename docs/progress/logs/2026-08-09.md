# 2026-08-09 开发日志

## 目标

修复 Windows PowerShell 下 RoleMux 调用 Agy/Grok/OpenCode 时的 provider 可用性、非交互输出和后台 monitor 时序问题，并刷新已安装 Skill/plugin。

## 修复

- PowerShell wrapper 不会继承到子进程；文档明确由启动 RoleMux 的 shell 显式导出代理变量，并固定逗号列表 quoting 规则。
- Agy 默认仍使用 PTY；`ROLEMUX_AGY_TRANSPORT=process` 使用 `--disable-slash-commands --output-format stream-json`，由 workflow runner 提取最终 `result.response`。
- `doctor --probe` 在读取固定成功 token 后结束 provider，避免 Agy 输出已到达但进程未退出造成误报 timeout。
- provider 在最终机器事件前失败时保留原始机器流，避免权限/工具失败被压成空产物。
- detached dispatch 只有在 `output.md` 写入后才把父 monitor 标为 terminal success/failed，消除 provider completion 与 artifact write 之间的可见竞态。
- Agy 工具权限保持 provider-owned；没有默认加入 `--dangerously-skip-permissions`，需要时由调用者显式通过 `ROLEMUX_PROVIDER_AGY_ARGS_PREFIX` 传入。

## 验证

- `npm run verify:release`：35 个 test files、169 个 unit tests、3 个 CLI E2E、build、pack dry-run 和 `git diff --check` 全部通过。
- 真实 `rolemux doctor --providers 'agy,grok,opencode' --probe`：三者 executable 与 probe 均通过。
- 真实 workflow 纯回答：Agy、Grok、OpenCode 均返回 `ROLEMUX_E2E_OK`，exit code 为 0。
- `install --codex --claude --codex-plugin` 完成 Codex App plugin source/cache 刷新；安装 Skill 与仓库源 SHA-256 一致。

## 边界

- Agy 在 headless 环境执行需要工具的任务时仍会遵循自身权限询问；若未显式批准，RoleMux 会记录失败和保留机器流，不假报 success。
